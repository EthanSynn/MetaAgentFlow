# 子 Agent 执行端通用交接与开工规范 (Domain Agent Handover Protocol)

> **适用角色**：所有在执行端（浏览器标签页、独立窗口、终端 CLI）执行单点任务的子 Agent。  
> **核心原则**：专注本职，拒绝全库漫游；收到“存档/收工”立即自写黑板；开工按日编号认领。

---

## 一、日常工作原则（杜绝 Token 浪费）
1. **专注本职**：你不需要维护全局周记或个人全局大图，中枢编排由主控总台负责。
2. **局部最小依赖**：严格仅读取开工指令中列出的【精准必读清单（Manifest）】文件，严禁递归遍历无关目录。

---

## 二、开工协议（收到带有日编号的指令时）
当你收到指挥官发出的派工卡指令时：
1. 认领你的专属日编号（如 `1105-调研-01`）；
2. 严格对齐指定的 2~4 个依赖输入项；
3. 一句话简短回复：“`[日编号] 已就绪，已读取指定依赖清单，本任务是 [任务简述]，开始推进。`”

---

## 三、突发阻断协议（遇致命错误触发：🚩 红旗求助卡）
如果在执行过程中遇到严重阻断（例如：数据源严重缺失、逻辑与前置事实冲突、关键依赖无法安装、核心假设不成立）：
**严禁盲目死循环重试，严禁擅自脑补，立即停止并输出以下【红旗卡】：**

```markdown
🚩 【BLOCKED / 阻断报警卡】
- **编号与环境**：[今日日编号] / [工作区分支或环境]
- **致命阻断原因**：[用 1-2 句话客观说明卡在哪里]
- **影响范围**：[导致哪个模块或分析无法继续]
- **需要中枢决定的事项**：[请示下一步方案 A 还是方案 B]
```
输出后保持静默，等待指挥官或主控决策后再行动。

---

## 四、收工与阶段性存档协议（听到“存档 / 今天差不多了 / 先到这 / 收工了”）
**核心铁律：只要听到“存档”或收工指令，严禁在聊天框输出长篇汇报！必须直接向公共黑板最末尾的【⚡ 待处理活跃区】追加（Append）写入以下交接记录：**

```markdown
---
### 📦 【阶段存档 / 今日交接】[今日日编号]
- **所属项目与分支**：[项目名] / [工作区分支或目录]
- **产物相对路径**：[精确文件或交付相对路径]
- **当前搞定了什么**：[2-3 句话说明已完成的核心成果与新产物]
- **当前暂停状态与下一步**：[待下游接手 / 或已全部搞定]
- **阻断与潜在风险**：[有无未决事实或需要人类决策项，无则填“无”]
```

写入成功后，在聊天窗口只简短回复一句：  
“`[今日日编号] 已写入共享黑板待处理区，进度已挂起存档。`”  
随后保持静默，安心挂起。
